# Asset map — PODOS private proposal platform, technical menu-illustration library

Owner: image art director. Generator: `gpt-image-2` via `~/.claude/skills/ayesmaj-premium-web/scripts/generate-image.mjs`.
Every asset below has its full prompt saved beside it as `<id>.prompt.txt` and its request/usage sidecar as `<id>.generation.json` in `public/visuals/menu/`.

Rules that govern this library:

- One image = one placement. Nothing here reuses the photographic `public/visuals/configurator/` library, and no file here is placed twice.
- Essential copy stays in HTML. No image carries text, labels, numbers or logos.
- These are conceptual technical illustrations, not photographs and not engineering drawings of a specific delivered unit. Where a page could mislead, caption them as illustrations.
- Alt text describes what is drawn, not product specifications.

## Image style bible (shared by every asset)

Full prompt text: `public/visuals/menu/_style-bible.txt` (orthographic cards) and `public/visuals/menu/_style-bible-iso.txt` (axonometric hero and PDF cover). Summary:

| Dimension | Rule |
|---|---|
| Visual mode | Clean orthographic technical illustration, engineering-elevation manner; premium spec-drawing feel |
| Projection | Cards: strict straight-on front / side / plan view, zero perspective. Hero + PDF cover only: flat parallel axonometric three-quarter |
| Background | Porcelain white `#F7F8FA` with a faint cobalt blueprint grid (~8% opacity, major squares ~1/10 width, fainter subdivisions), fading toward edges. No floor, room, horizon, sky |
| Equipment | Matte black to dark graphite `#111317`–`#2A2E35`, soft matte shading, no gloss or reflections; seams, vents, rails, fasteners as thin light-gray construction lines `#9AA3AD` |
| Flow grammar | Cobalt `#2563EB` = primary / supply / power / incoming. Cyan `#22D3EE` = secondary / return / data / exhaust. Straight lines, right-angle bends, small solid triangular heads, flat fill |
| State color | Green `#22C55E` only as a small enabled / online / accepted indicator, only where the subject calls for it |
| Grounding | One soft, restrained shadow directly under the equipment |
| Composition | One concept per image, centered, uncropped, ~12% safe padding on every side |
| Proportion system | 42U rack = 1 unit wide x 2.6 tall on leveling feet; support cabinets share that height or a clean half height; PODOS pod = ~3.5 x 1 units, rounded end caps, low raised roof-panel band, six equal side panels, black skid base with feet (matches the approved pod reference `public/new pod.png`) |
| Exclusions | Text, numbers, labels, dimension callouts, logos, watermarks, people, hands, environment, perspective, photographic stock look, dramatic light, lens effects, sci-fi glow, neon, purple/pink, orange, duplicate subjects, clutter, cropped edges |

Generation protocol used: round 1 low-quality composition probes of all 19 assets (reviewed on a contact sheet against the locked reference), prompt corrections to `pwr-n1` (B path forced to cyan), `net-hbw` (single-line mesh instead of doubled links) and `pdf-cover-pod` (wider side margins), then round 2 production at `--quality high`. Totals: 38 generations (19 probes + 19 production), 0 failures, 0 retries. Production WebP sizes 40–203 KB (all under 400 KB); `pdf-cover-pod.png` 1.5 MB (PNG required by react-pdf).

## Loading and optimization

- WebP q88 is written directly by the generator; no second encode. The PDF cover is PNG by requirement.
- Cards: `next/image` with `width={1600} height={1200}`, `sizes` matching the card grid (about `(min-width: 1024px) 33vw, (min-width: 640px) 50vw, 100vw`), lazy by default.
- Hero: the only candidate for `priority`; give it `sizes="100vw"` and use `object-position: right center` on narrow viewports.
- Blueprint field: CSS background, never an LCP element.
- `next/image` will serve AVIF/WebP variants from these sources; keep the originals as the single source of truth.
