# Proposal Redesign — Comparison Report

Date: 2026-09-01 · Test case: PODOS-1002 (POD-EST-2026-0002), rendered in design-preview mode (real numbers, placeholder text masked).
Evidence: `docs/proposal-qa/` (PDFs + 200 DPI page renders + viewer capture; regenerated by `node --env-file=.env.local scripts/proposal-qa.mjs <publicId> <formal|preliminary>`).

## Before → after

| | Before | After |
|---|---|---|
| Renderer | `@react-pdf/renderer` (own layout engine, no CSS Grid/SVG filters) + a separate scrolling web document | **One** paginated HTML/CSS/SVG component (`ProposalPrint`) — the web viewer, the admin preview and the PDF are the same DOM; headless Chrome prints it |
| Formal page count | 6 sparse pages | **Exactly 3** (cover · Your PODOS system · Commercial proposal); appendix only if line items overflow (>16 rows) |
| Preliminary | none (same 6-page PDF for everything) | **2 pages** (cover · configuration estimate) |
| Repetition | price range printed on 4 pages | totals once (page 3 panel), metrics once (cover) |
| Pod visual | 1 small cover image | large framed cover hero, technical cutaway with 6 numbered SVG callouts, deployment visual — all GPT Image 2 edits of the approved render |
| Data safety | none — `gsg` / `33333 MW` / `fff` printed and signed | `validateProposalForRelease()` blocks release (10 error classes, 6 warning classes); invalid proposals render only as a watermarked design preview with masked text; names proper-cased |
| Typography | react-pdf Helvetica fallback | Geist 800 display (title 36pt), Inter Tight text 9.5pt/1.45, tabular numerals everywhere (founder rule: no mono family) |
| Background | flat white | vector system: porcelain base, upper-right cobalt radial, 3% grid, corner brackets, one page-specific energy path |
| Design control | none | `estimates.design` + Proposal Design panel: page mode, visuals, 8 section toggles, signature block, validity override, watermark, download/comments |
| Integrity | none | footer hash on every page (data fingerprint), `X-Document-SHA256` on every PDF, `record_proposal_pdf` RPC for per-version records |
| Assets | 2 static files | 3 controlled assets, regenerable from `/ops/design` (stored in DB, served by `/api/proposal-assets/[type]`, cache-busted by hash) |

## Known limits / follow-ups

- PODOS-1002 stays a design preview until its placeholder data is corrected (or it is reopened/voided and rebuilt). The release action refuses it.
- Web viewer: fit-width + zoom (CSS `zoom`), download when permitted. Thumbnails, comments and revision requests are not built yet (the `allow_comments` setting is stored and ready).
- `OPENAI_API_KEY` must exist in the Vercel environment for `/ops/design` regeneration; without it the action reports "not configured" and the shipped assets keep being used.
- The PDF function relies on `@sparticuz/chromium` on Vercel (traced via `outputFileTracingIncludes`); first cold start is a few seconds.
